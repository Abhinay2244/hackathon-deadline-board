What This App Does

A browser-only dashboard for students juggling multiple hackathons. Add hackathons with deadlines; each becomes a card with a live countdown and a "Can I finish?" feasibility meter (Safe / Tight / Impossible) based on per-task hour estimates. A "What to do today" panel at the top prioritizes unfinished tasks by urgency. All data persists in localStorage — no backend, no login.

Reference Route — "Tick a Task"

Follow the core interaction through three code locations:

1. Entry Point — window.toggleTask(hackathonId, taskKey)

File: app.js ~line 142

Called from checkbox onchange on both cards and the "What to do today" panel. Finds the hackathon, enforces the Submit dependency rule (unticking a prereq auto-unticks Submit), flips the boolean, checks for completion, triggers confetti, then save() + render().

2. Feasibility Engine — calculateStatus(h)

File: app.js ~line 31

Sums TASK_HOURS of unfinished tasks (Idea 2, Build 8, README 1, Demo 3, Submit 1 = 15h total). Computes hoursLeft until deadline. Returns {type, label, reason, hint, hoursCompleted, hoursNeeded} where type ∈ safe tight impossible submitted expired.

3. Visual Update — renderCard(h, status)

File: app.js ~line 222

Builds card HTML: progress % = hoursCompleted/15, badge + left-border color from status.type, reason line (e.g., "Build, README left, about 9 hours needed, 4.5h left"), pace hint, checklist with Submit disabled + lock hint when prereqs unmet.

To Change This, Start Here

Adjust task hour estimates

Edit TASK_HOURS in app.js (line ~23). Progress %, status thresholds, reason text, and pace hint all update automatically.

Modify status thresholds

Edit the hoursNeeded > hoursLeft (Impossible) and hoursNeeded > hoursLeft * 0.6 (Tight) comparisons in calculateStatus().

Change "What to do today" prioritization

Edit renderTodoPanel() logic (line ~269): urgent hackathon gets 3 tasks vs 1–2 from others; 48h threshold; max 6 items total.

Tweak the dark theme

Colors are CSS custom-properties-friendly in style.css: #0d1117 (bg), #161b22 (cards), #238636 (safe), #d29922 (tight), #f85149 (impossible).

A Practice to Reuse

Decision: Define task hour estimates as a single constant object (TASK_HOURS) rather than a flat "3 hours per task" multiplier.

Evidence: app.js lines 23–29 (data), 41–42 (engine), 247–250 (progress %), 241–244 (reason line). Changing one object ripples through status calculation, progress bar, reason text, and pace hint without touching the logic.

How to apply next time: When a feature has multiple derived outputs (badges, progress, text, hints), express the source-of-truth data first. Ask the agent: "Here's the data shape — derive everything from it." This keeps derived views consistent and makes later tuning a one-line edit.
